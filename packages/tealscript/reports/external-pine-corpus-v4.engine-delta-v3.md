## Runner Provenance

`packages/tealscript/scripts/run-external-pine-corpus.ts` imports `parse` from `../src/parser/parser.ts`, `checkProgram` from `../src/semantic/checker.ts`, and `tryCompile` from `../src/runtime/codegen/execute.ts`. There is no `dist` directory and the script does not load a cached report or build output. `parser.ts` delegates to the checked-in `packages/tealscript/src/parser/generated.js`; that generated parser is therefore part of the source path used by the rerun. Semantic and compiled execution are loaded from the TypeScript source.

The runner currently calls `checkProgram(ast)` and `tryCompile(ast)` without a `libraries` option. This means the corpus run does not model an application-provided host library registry. The post-library rows that resolve their official import now fail on the next missing export, proving that the import-resolution path did run; the alias-fallback rows remain unchanged because their resolver path still reports the missing imported member. This is an integration limitation of the harness, not evidence that the source changes were absent.
