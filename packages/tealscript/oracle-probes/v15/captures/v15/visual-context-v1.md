# TradingView v15 visual capture context v1

Eight frozen v15 sources have native RUNS receipts: bgcolor, plotarrow, barcolor and plotchar, each with series and zero controls. Raw CSVs, original Chrome MCP PNGs, source SHA, native chart context and ordered Pine log receipts are retained. Other v15 sources are pending.

The qualifying bgcolor pair is series attempt 3 with zero-control attempt 1, using the **replay-phase9/11/12/31-paired-v1** witnesses. The timestamps, host OHLC, 32-bar visible range, right offset, pixel spacing, 954-pixel pane widths and pane heights match at each stop. Series attempt 2 uses an earlier, shorter pane height. The zero-control attempt 1 **replay-phase31-after-v1** frame has the intended timestamp but a 232-pixel pane width because Pine Editor was open. Its **replay-phase31-before-v1** frame instead records literal n=20023 / phase23 and a different timestamp, so its filename does not establish the intended phase31. Both are retained as nonqualifying pair attempts. The additional **phase9-matched** frame predates reopening the Data Window and is not the selected pair frame.

For plotarrow, use both attempt 1 **renderer-phase9/11/12/31-v1** sets, substituting the series **renderer-phase11-settled-v1** receipt at phase11. The earlier series renderer-phase11 frame caught a partial Replay OHLC update and is nonqualifying for the matched pair. These add the actual child renderer objects, including native arrow x/y/height, to the earlier placement-index frames. For barcolor, use both attempt 1 **replay-phase7/15-paired-v1** sets, which include the main-series candle renderer colors and coordinates. For plotchar, use both attempt 1 **renderer-phase7/15-v1** sets, including the native char renderer's X glyph x/y coordinates and size. Glyph pair pane width is 948 pixels; arrow and candle pairs use 954 pixels. The dimensions are matched within each pair, not assumed identical across families.

Each witness keeps the source rows and host timestamps alongside actual native destination indices and coordinates. Native chart index is separate from the source's exported n/N. Warmup source rows may use native negative sentinel indices. No source index is inferred from CSV ordinal. Raw null/offscreen geometry is preserved; only exposed finite renderer coordinates are usable for pixel comparisons. The native renderer state is the evidence; no universal series-offset rule, live-tick behavior, internal renderer algorithm or engine parity claim is made here.

The source CSVs were exported at the initial fixed Replay cutoff. Later phase frames retain their native source/host rows directly. All pair stops use unchanged source defaults, BINANCE:BTCUSDT, 2-minute standard candles, Etc/UTC and 100% requested Chrome zoom (DPR 2). Compilation succeeded for all eight. Empty native Pine logs are preserved as empty receipts.
