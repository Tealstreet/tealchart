## Engine State

TealScript has one evaluation engine: compiled codegen. The interpreter and
closure backend are deleted. `executeScript(...)` is a public wrapper over the
compiled path, so any compiled-vs-public differential now proves wrapper
consistency only, not Pine semantics.

Official TradingView libraries are compatibility builtins implemented from
published docs. Third-party TradingView imports are unsupported by design:
Pine runs in TradingView's closed server-side runtime, and third-party library
source is not a network-resolvable artifact TealScript can fetch or scrape.

## Operating Rules

1. Judge every script by its declared Pine version; TealScript supports v3
   through v6.
2. Quote corpus acceptance and value-vector coverage separately. Corpus support
   means a script ran and emitted normalized output; vectors and traces measure
   values.
3. Every quoted figure must name its report and measurement commit. If the
   figure has no commit, rerun or treat it as stale.
4. A surprising movement is an instrument suspect before it is an engine
   finding. Check pinned source hashes, fixture profile, stage, and diagnostic.
5. Do not convert uncertainty into implementation. If the reference does not
   specify a value or invalid-input consequence, keep it trace-required or
   trace-undetermined.
6. A fix and its oracle must not come from the same source. Self-consistency
   checks prove only that a change agrees with itself; closed verification
   needs a published formula, reference composition, manual-specified result,
   hand-derived arithmetic, or trace. Tonight's examples were partial-exit
   average price, which needed an external cost-basis oracle after passing
   ledger invariants, and the differential harness, which agreed with itself
   864 times and proved no Pine semantics.
7. Independent evidence can still be incomplete evidence. A single manual page,
   reference snapshot, or corpus-derived table is not the whole TradingView
   reference surface. When sources disagree or one source is silent, check the
   live reference, declared version, published scripts, or compiler evidence
   before converting absence into a rejection rule. The `matrix.sort:sort_field`
   reversal is the canonical example: one doc page omitted it, while the live v6
   reference documents it for UDT matrix sorting. Function call-site history
   exposed another failure mode: an assignment premise can become a source too.
   A green fix and green vector are not enough if both fail to distinguish the
   assigner's premise from the reference rule.

## Reproduction

The TealScript typecheck package script sets a 12GB Node heap. It was first
raised to 8GB when the post-parity TypeScript graph outgrew Node's default 4GB
heap, then raised again on 2026-09-12 after the package typecheck OOMed at
`--max-old-space-size=8192` before reaching diagnostics. Do not trim the heap
without a fresh cold typecheck measurement; a lower number can turn the
load-bearing gate into an OOM-killed process rather than a TypeScript result.
The first 12GB verification in this worktree completed with no diagnostics in
6:57 wall time on 2026-09-12 while the host was still visibly CPU-constrained.
A subsequent post-merge 12GB verification completed with no diagnostics in
2:16 wall time on the same date. That healthy-gate wall time is up from an
earlier 86s baseline as the TypeScript graph, reports, guards, and value-vector
surface grew; future heap changes should record elapsed time too.

yarn workspace @tealstreet/tealscript typecheck

yarn workspace @tealstreet/tealchart test-ci

or a clean checked-out measurement commit, and record the source manifest hashes
