- `session.ismarket` is a host-data capability gap, not a parser or language
  defect. TradingView defines exchange sessions as instrument properties used
  by chart/request datasets, so TealScript needs a host-supplied session
  classifier keyed by symbol/exchange, timezone, chart session selection, bar
  timestamp, regular/extended market definitions, holidays, and early closes.
  The current runtime fails loudly when that classifier is unavailable; adding
  it is a separate datafeed/calendar integration rather than a syntax fix.
- Library-import decision for T13: there is no network-resolvable TradingView
  library source for TealScript, ever, by definition. Pine executes inside
  TradingView's closed server-side runtime, and script source is not an
  artifact TradingView exposes; this is not a missing endpoint, a cache miss,
  or a terms-of-service obstacle that could become fetchable later. Any future
  proposal to fetch, scrape, or resolve library source from TradingView is
  wrong at the premise and should be rejected without scoping. TradingView
  third-party library imports are unsupported by design and permanently so.
  Official TradingView standard libraries are supported by implementing their
  exported APIs as TealScript builtins from official TradingView documentation,
  with version-pinned surfaces such as `TradingView/ta/7`, `/9`, and `/10`
  resolved exactly and unsupported versions failing loudly. The positive
  roadmap is Tealstreet's own library ecosystem and module linker: Tealstreet
  builds, hosts, links, and reviews its own shared libraries on its own terms.
  Official TradingView std libs are compatibility builtins, not source
  resolution; everything beyond that belongs to Tealstreet's linker, not
  TradingView accounts, and is explicitly not part of the current work.

## Invariants

- Compiled is the only TealScript execution engine.
- Unsupported compiled execution fails loudly and keeps `RuntimeProfile.fallbackReason`/`fallbackDiagnostics` visible.
- Missing request providers remain warnings; unsupported execution remains errors.
- Runtime sites that continue after ordinary per-bar errors must increment swallowed-error accounting and retain the first site/message/bar index.
- User-facing visual strings are labels, not identity. Plot and alertcondition identity must come from declarations/call sites while preserving first-occurrence legacy plot IDs for persisted Tealchart style overrides.
- Missing Pine declaration precision is `undefined`; Tealchart decides display precision at label render time.
- Corpus reports use repo-root-relative output paths so `yarn workspace` cannot create nested report trees under `packages/tealscript/packages/`.
- New product-path evidence must reuse the shared output comparator; do not write a second definition of equivalent output.
