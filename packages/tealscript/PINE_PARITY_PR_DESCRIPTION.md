This branch turns TealScript Pine parity from package-local capability into
product-path support. It expands Pine v6 parser/runtime coverage, wires
host-backed request data and imported libraries through the worker and web app,
normalizes Tealchart rendering output, and adds measurement gates for the paths
users actually hit: paste validation, worker execution, request resolution,
library registration, initial load, realtime updates, and rendering handoff.

The headline result is that the production worker path now measures the same
realistic 89-script corpus/composite set that the compiler baseline measures,
instead of only calling `tryCompile()` in-package. Runtime request discovery
closed the original bridge gap from 60/89 compiled product executions to 89/89
for request/import support, and the old product-worker realtime safety gate was
removed after direct compiled replay plus worker composite tests proved the
classified stateful intrabar rows execute and match as compiled. Native mobile
now intentionally has no inline TealScript executor until the bundled WebView
compiled host lands.

## What Changed

### Production Worker, Requests, and Libraries

- Added a serializable worker request-data bridge for `request.*` instead of
  trying to structured-clone function-bearing datafeeds.
- Provider-data absence through that bridge now surfaces as a nonfatal
  `request-data-unavailable` diagnostic in Tealchart while Pine-side request
  values remain `na`/empty where appropriate.
- Routed `request.security`, `request.security_lower_tf`, `request.seed`,
  `request.currency_rate`, `request.economic`, `request.dividends`,
  `request.splits`, `request.earnings`, `request.financial`, `request.quandl`,
  `request.footprint`, `footprint.*` including price-addressed row lookup, and
  `volume_row.*` through the same host-backed provider seam.
- Added runtime request discovery for series-varying request arguments: the
  worker runs a hidden compiled discovery pass, records concrete requests,
  warms the cache, discards hidden plots/drawings/alerts/logs/strategy state,
  and reruns the visible pass.
- Unsupported compiled execution surfaces as fatal diagnostics instead of
  falling back to another engine.
- User-facing TealScript diagnostics have a structural taxonomy: true
  script/runtime failures and compiled realtime unsupported constructs are
  `severity: 'error'`, provider absence is `severity: 'warning'`, and save
  validation preserves stable failure kind plus checker diagnostic codes.
- Web worker telemetry uses that taxonomy without shipping private TealScript
  messages, symbols, source constructs, arbitrary tags, or extra data to Sentry.
- The native TealScript path now follows the same diagnostic taxonomy where it
  applies: mobile request-data provider absence is a nonfatal warning, while
  parse/runtime script failures remain errors.
- Mobile hosts can supply a deterministic Pine library registry to
  `SkiaTealchart`; the hidden WebView compiled host is the mobile execution path
  that will consume it.
- Mobile hosts can also supply a synchronous `RequestDatafeed`, so
  request-backed scripts receive real provider data on native; the no-provider
  case remains a nonfatal `request-data-unavailable` warning.
- Before the legacy runtime was removed, it was profiled against the existing
  composite benchmarks. Direct global scalar `input.*` declarations were cached
  after bar-0 registration/validation, and UDF/imported-UDF execution cached
  immutable call metadata while preserving per-callsite state. TA-window and
  ordered-call helpers avoided avoidable per-call allocation. Measured legacy
  runtime cost moved from 1817 to 1421 us/bar, 683 to 554 us/bar, and 887 to 727 us/bar
  respectively on the shared Mac benchmark runs.
- Sam chose compiled as the single TealScript engine. The no-eval backend and
  legacy runtime are being removed by direct cutover; mobile will run compiled in a
  hidden WebView rather than through inline `MobileIndicatorManager` execution.
- T110 made backend execution observable without changing defaults:
  Tealchart emits a compact backend/timing/output summary for every accepted
  worker execution result and runtime halt, and apps/web reports it through the
  existing Sentry path with local sampling/caps and a static fingerprinted
  message. The telemetry names selected backend, actual execution mode,
  selection source, elapsed-time/bar-count buckets, empty-output runs, and
  runtime errors by backend while deliberately excluding script ids, source
  text, symbols, imports, line/column, runtime messages, raw fallback reasons,
  arbitrary tags, and arbitrary extra.
- Wired the web app's TealScript library registry into
  `TealchartDirectWeb.tsx`, so imported Pine libraries reach compiled worker
  execution instead of staying latent package support.
- Added an end-to-end paste journey test: save validation with imports, worker
  execution through a seeded bridge, plot parity against the legacy runtime,
  Tealchart render handoff, and actionable save diagnostics with line/symbol
  context.

## Plausible Wrong-Output Bugs Found

These were not clean crashes. They produced plausible output, silently wrong
values, or path-dependent behaviour that existing implementation-derived
fixtures could miss.

- `ta.supertrend()` returned the right line but inverted `direction` polarity
  relative to the public Pine idiom: `direction < 0` means uptrend and
  `direction > 0` means downtrend. Existing fixtures had encoded the inverted
  value as expected output.
- `ta.adx` resolved but never became finite under the warmup semantics users
  expect.
- Several `ta.*` warmup paths emitted plausible numbers before Pine's first
  valid bar.
- Compiled stateful `ta.*` calls inside UDFs shared state across call sites.
- Nested UDF stateful `ta.*` calls also shared state before call-chain-local
  isolation.
- `input.source()` overrides were ignored in compiled request/subprogram paths.
- Compiled input validation accepted defaults outside `options`, below
  `minval`, and above `maxval` while the legacy runtime rejected them.
- `runtime.error()` inside compiled `request.security()` expressions was
  swallowed as a per-request-bar failure and returned `na` instead of halting.
- Compiled request expressions could also swallow unresolved request-scope
  dependency errors and quietly return `na`; T126 made every intentional
  continuation site countable in `RuntimeProfile.swallowedErrors` and corpus
  rows, then closed request-expression swallow counts to zero on both corpora.
- Array edge cases returned plausible values instead of Pine-style errors:
  negative/oversized construction, empty first/last/pop/shift, and growth past
  100,000 through push/unshift/insert/concat.
- Strategy break-even trades counted as losses.
- `process_orders_on_close` leaked entry-bar high/low into max runup/drawdown.
- Compiled `syminfo.main_tickerid` returned `undefined` instead of falling back
  to `tickerid` then `ticker`.
- `display.all` missed `display.pine_screener`, so it was `15` instead of
  `31`.
- `plotarrow` appended stale `colorup`/`colordown` tick arrays instead of
  replacing at `bar_index`.

Realtime re-entry bugs/classes fixed or classified:

- Interpreter `updateBar(...)` skipped imported-library binding re-registration
  and failed calls such as `rt.adjusted(...)`.
- Imported function returns leaked source-aware wrapper objects into arithmetic,
  producing user-visible `[object Object]...` output on the fallback path.
- Re-entry scope snapshots did not clone plain array-backed state, corrupting
  stateful builtin histories and strategy ledger replay.
- Static/per-bar visual outputs diverged on re-entry: `hline` received
  synthetic per-bar values and `plotarrow` colour arrays appended stale tick
  data.
- The compiled worker realtime path is intentionally classified for stateful
  intrabar shapes it cannot prove safe: `varip`, persistent mutable tuple
  state, persistent collection mutation, and compound mutation of persistent
  state. These now fall back visibly instead of silently serving stateless
  compiled intrabar output.

## Decisions and Tradeoffs

- Recursion is a deliberate TealScript superset. Pine v6 rejects recursion, but
  TealScript runs direct and mutual recursion with the existing max-depth
  guard. The checker emits a warning naming the cycle and saying the script
  will not run on TradingView; it does not block execution.
- Missing provider data returns `na` where Pine semantics allow it. Missing
  bridge plumbing, non-convergent request discovery, and realtime-unsafe
  compiled paths surface visible `RuntimeProfile.fallbackReason` values instead
  of silently falling back.
- Runtime request discovery is bounded to three fetch rounds per generation.
  Scripts that keep revealing new request contexts stay visible as
  `unpreloadable-request-data: discovery-not-converged:*` rather than looping
  forever.
- The incremental compiled VM was assessed and deliberately not built. The
  current compiled realtime path reconstructs from the bar window, while the
  legacy runtime maintains incremental same-bar state. A robust compiled VM would
  require a session runtime owning generated instances, execution context,
  plots, drawings, alerts, logs, strategy ledger, request caches, inputs,
  library state, rollback/commit, and discovery fork semantics. Estimated cost:
  roughly 600-1200 production/test lines for indicator realtime semantics, more
  if strategy and drawing lifecycle are completed in the same pass.
- Instead of building that VM now, this branch uses a conservative realtime
  safety detector. False positives cost realtime speed; false negatives corrupt
  intrabar values. The detector therefore biases toward legacy runtime fallback
  when unsure, and the residual cost is measured.

## Reviewer Notes

The central risk on this branch was repeatedly the same: tests written from our
own output can certify our own bugs. This branch now treats that as an explicit
hazard. The meaningful claims are backed by independent manual-index audits,
literal expected values with declared provenance, compiled-only
oracles that exercise the real path under test, and production-path baselines
through the worker, request bridge, web library registry, and render layer.
